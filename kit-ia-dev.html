As 10 skills

Ativam sozinhas quando o pedido combina com o que fazem — você não precisa chamar nenhuma pelo nome. Até serem ativadas, custam praticamente nada de contexto.

Code Review01/10

Ativa quando: você pede uma revisão, quer um diff checado antes de commitar/abrir PR, ou pergunta se o código está bom.

"Revisa esse código antes de eu commitar"

Organiza os achados por severidade — bloqueante, deveria corrigir, considerar — cruzando com as regras de negócio e segurança já documentadas no projeto.

Debug Assistant02/10

Ativa quando: você reporta um bug, cola um erro/stack trace, ou diz que "funcionava antes e agora não".

"Esse erro está aparecendo: [cole o erro]"

Processo estruturado: reproduzir → isolar → diagnosticar a causa raiz (não só o sintoma) → corrigir com um teste que prova a correção.

PR Writer03/10

Ativa quando: você pede pra abrir um PR ou escrever a descrição de um PR.

"Escreve a descrição do PR pra essa branch"

Lê o diff real e o histórico de commits — não escreve a partir da conversa, que pode ter se distanciado do código.

Test Generator04/10

Ativa quando: você pede para adicionar testes ou melhorar cobertura.

"Escreve testes pra essa função"

Cobre comportamento esperado e casos de borda reais — não só o caminho feliz — com valores determinísticos pra evitar testes instáveis.

Doc Writer05/10

Ativa quando: você pede para documentar uma função, atualizar um README, ou explicar código.

"Documenta essa função"

Documenta o "porquê", nunca o óbvio — evita comentário que só repete o que a linha de código já diz.

Frontend Design06/10

Ativa quando: você está construindo uma UI nova, uma página, um componente, ou reformulando uma interface.

"Cria uma landing page pra esse produto"

Evita o padrão genérico por padrão — decisões deliberadas de tipografia e hierarquia, acessibilidade e estados reais (carregando, vazio, erro) já incluídos.

Security Audit07/10

Ativa quando: você pede uma revisão de segurança, ou está mexendo em autenticação, pagamentos ou dados pessoais.

"Essa rota de pagamento está segura?"

Não entrega checklist genérico — pesquisa os riscos reais da sua stack e explica o caminho de exploração de cada achado.

API Design08/10

Ativa quando: você está criando ou revisando um endpoint de API.

"Cria um endpoint pra listar os pedidos do usuário"

Garante consistência com o resto da API — formato de erro, nomenclatura, paginação, status HTTP corretos, validação na fronteira.

Refactor Guide09/10

Ativa quando: você pede para refatorar, limpar, simplificar ou reestruturar código sem mudar o comportamento.

"Essa função ficou grande demais, refatora ela"

Estabelece uma rede de segurança de testes antes de mexer em qualquer coisa, e muda em passos pequenos e verificáveis.

Feature Planner10/10

Ativa quando: antes de escrever código para uma feature nova, mudança não-trivial, ou tarefa com escopo pouco claro.

"Preciso adicionar notificações, me ajuda a planejar"

Faz perguntas quando o escopo está ambíguo, escreve um plano curto e verificável, e só avança pro código depois de confirmação.

Que tipo de projeto é esse?

O sistema se adapta durante a entrevista de setup, mas alguns padrões se repetem — o que priorizar em cada cenário.

Tipo de projetoPriorize
Projeto novo, do zeroCLAUDE.md + engineering-standards.md logo no início. "Ainda não sei" é resposta normal em business-rules.md. Feature Planner tende a ser a mais usada nas primeiras semanas.
Projeto existente, sem documentaçãoPeça pra IA ler o código antes de entrevistar você — costuma revelar inconsistências reais de padrão que vale documentar como "oficial".
Múltiplos desenvolvedoresbusiness-rules.md revisado em grupo, não só individual. A seção "Keeping This File Current" do CLAUDE.md fica ainda mais importante em equipe.
API ou backend puroAPI Design, Security Audit e Test Generator são as mais usadas. Frontend Design praticamente não entra em jogo — sem custo por estar instalada.
Pagamentos ou dados sensíveisDetalhe bastante business-rules.md e security.md — são os dois arquivos que Code Review cruza automaticamente. Rode Security Audit sobre o projeto inteiro após o setup.
Monorepo ou múltiplos serviçosarchitecture.md vira um dos arquivos mais importantes. Considere .claude/rules/ com escopo por pasta desde o início.

Comandos que você vai usar mais

O comando completo de setup inicial está no Workflow 1 do guia PDF — de propósito não resumido aqui, porque precisa ser colado exatamente como está.

Adicionar uma ferramenta nova (ex: já tem Claude Code, agora quer Cursor também)
Hoje eu só tenho CLAUDE.md configurado neste projeto. Agora também uso [ferramenta]. Siga a instrução de multi-tool setup: crie o AGENTS.md com o conteúdo que já está no CLAUDE.md, transforme o CLAUDE.md num wrapper fino que importa o AGENTS.md, e crie o arquivo de escopo específico dessa ferramenta se ela tiver um.
Atualizar recomendações que podem estar desatualizadas
Pesquise as ferramentas de lint e teste padrão para [linguagem] e atualize o CLAUDE.md com o que for real.
Forçar uma skill específica, se ela não ativou sozinha
Usa a skill de [nome da skill] em [o que você quer analisar]
Projeto existente sem documentação — antes da entrevista
Antes de me entrevistar, dê uma olhada nos arquivos principais do projeto para entender os padrões que já existem. Depois me pergunte só o que não conseguir inferir do código — decisões de negócio, coisas que não estão explícitas no código, e o que você percebeu que parece inconsistente.

Problemas comuns

Organizado por sintoma. Para o passo a passo completo de cada correção, veja Troubleshooting no guia PDF.

  • A IA só preencheu os placeholders com coisas genéricas, sem entrevistarO comando de setup foi resumido/reescrito. Cole o comando completo do Workflow 1 exatamente como está, sem alterações.
  • Uma skill não ativa quando deveriaConfirme se a pasta está no lugar certo pra sua ferramenta (veja COMO-INSTALAR.md) ou mencione a skill diretamente: "usa a skill de [nome]".
  • O hook não bloqueia o commit mesmo com lint falhandoConfira se .claude/settings.json foi criado e se os comandos de lint/typecheck foram preenchidos de verdade, não deixados como placeholder.
  • Minha ferramenta (Cursor, etc.) não está lendo o CLAUDE.mdEsperado — cada ferramenta lê um arquivo diferente. Confirme se o AGENTS.md existe; se não, use o comando "adicionar ferramenta nova" acima.
  • Uma regra documentada não está sendo respeitada em sessão novaConfirme que o CLAUDE.md referencia o arquivo certo na seção "Deeper Context" — link quebrado impede o carregamento sob demanda.

10 erros que fazem a IA gerar código ruim

1 página · imprimível · cole ao lado do teclado
Cada erro abaixo é uma causa real de código genérico, inconsistente ou inseguro — não apenas estilo de escrita: são comportamentos que mudam o resultado. Confira antes de pedir algo grande para a IA.

01

Não ter nenhum arquivo de contexto

Toda sessão nova começa do zero — sem stack, convenções ou regras de negócio, a IA improvisa e você reexplica tudo de novo.

02

Arquivo de contexto gigante e genérico

Acima de aproximadamente 200 linhas, a precisão cai mesmo com a informação presente. Um arquivo genérico gerado automaticamente tende a sair pior do que não ter nenhum.

03

Pedir sem contexto específico

“Cria uma função que faça X” sem dizer stack, convenção ou onde isso encaixa no projeto real.

04

Regra de negócio crítica não documentada

A IA não tem como adivinhar o que “nunca pode dar errado” no seu domínio específico.

05

Aceitar o código sem revisão

Tratar a resposta da IA como pronta por padrão, sem checar se ela realmente resolveu o problema certo.

06

Não dar à IA meios de verificar o próprio trabalho

Sem teste automatizado ou hook de validação rodando, a IA não tem como confirmar se o que gerou realmente funciona — e não se autocorrige.

07

Deixar a IA inventar convenção própria

Sem padrão escrito, cada sessão decide nomenclatura e estrutura de um jeito diferente.

08

Pular o planejamento em mudanças grandes

Ir direto para o código numa feature não trivial costuma gerar retrabalho quando a abordagem não era a certa.

09

Confiar em conhecimento desatualizado

Regra antiga no seu contexto ou sugestão de API que a IA aprendeu antes do corte de treinamento — até 38% das sugestões usam algo já depreciado.

10

Instalar skills/prompts de terceiros sem revisar

Cerca de 1 em cada 3 skills públicas disponíveis hoje tem alguma falha de segurança real (Snyk, 2026).
